# 代码审查

专业的代码审查技能，帮助发现代码中的问题并提供改进建议。

## 何时使用

- 用户请求代码审查或代码检查
- 用户说 "review this code"、"审查代码"、"检查代码质量"
- Pull Request 审查
- 代码重构前的评估
- 安全审计

## 审查维度

### 1. 代码质量

| 检查项 | 说明 |
|--------|------|
| 可读性 | 变量/函数命名是否清晰，代码是否易读 |
| 一致性 | 代码风格是否一致，是否遵循项目规范 |
| 简洁性 | 是否有冗余代码，能否简化 |
| 注释 | 注释是否充分且有意义 |

### 2. 正确性

| 检查项 | 说明 |
|--------|------|
| 逻辑错误 | 条件判断、循环逻辑是否正确 |
| 边界条件 | 是否处理了边界情况 |
| 错误处理 | 异常是否被正确捕获和处理 |
| 类型安全 | 类型使用是否正确 |

### 3. 安全性

| 检查项 | 说明 |
|--------|------|
| 输入验证 | 用户输入是否经过验证 |
| 注入风险 | 是否有 SQL 注入、XSS 等风险 |
| 敏感数据 | 密码、密钥是否被正确处理 |
| 权限检查 | 是否有适当的权限验证 |

### 4. 性能

| 检查项 | 说明 |
|--------|------|
| 算法复杂度 | 是否使用了低效算法 |
| 内存使用 | 是否有内存泄漏或过度使用 |
| 数据库查询 | SQL 是否优化，是否有 N+1 问题 |

### 5. 可维护性

| 检查项 | 说明 |
|--------|------|
| 模块化 | 代码是否合理分割为模块 |
| 耦合度 | 模块间是否松耦合 |
| 测试覆盖 | 是否有足够的单元测试 |

## 工作流程

### 步骤一：理解上下文

- 了解代码的目的和功能
- 了解项目的编码规范
- 了解相关的业务逻辑

### 步骤二：快速浏览

- 获取代码整体结构
- 识别主要模块和组件
- 标记需要深入审查的区域

### 步骤三：详细审查

按维度逐一检查代码，记录发现的问题并提供改进建议。

### 步骤四：生成报告

```markdown
# 代码审查报告

## 概述
[代码的整体评价]

## 发现的问题

### 严重问题 (必须修复)
1. [问题描述]
   - 位置: file.py:123
   - 建议: [具体建议]

### 中等问题 (建议修复)
...

### 轻微问题 (可选优化)
...

## 优点
[代码做得好的地方]
```

## 最佳实践

1. **优先级排序**：按严重程度排序问题（严重 > 高 > 中 > 低）
2. **具体建议**：给出具体的代码改进建议，而不是模糊的建议
3. **保持礼貌**：以建设性的方式提出问题
4. **关注重点**：关注最重要的改进点，不要列出太多小问题

## 常见问题模式

### 安全问题

```typescript
// ❌ SQL 注入风险
const query = `SELECT * FROM users WHERE id = ${userId}`;

// ✅ 使用参数化查询
const query = 'SELECT * FROM users WHERE id = ?';
db.query(query, [userId]);
```

### 性能问题

```typescript
// ❌ N+1 查询问题
for (const user of users) {
  const posts = await getPosts(user.id);
}

// ✅ 批量查询
const posts = await getPostsByUserIds(users.map(u => u.id));
```

### 错误处理

```typescript
// ❌ 吞掉错误
try { await doSomething(); } catch (e) {}

// ✅ 正确处理错误
try {
  await doSomething();
} catch (e) {
  logger.error('Failed', e);
  throw new AppError('Operation failed', e);
}
```
