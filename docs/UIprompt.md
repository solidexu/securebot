终端多 Agent 协作聊天界面 - 前端交互设计说明
1. 整体布局与区域划分
界面运行在纯终端字符环境中，采用固定比例、刚性布局，各区域尺寸、边界、位置在交互全程保持稳定，不会因内容多少发生拉伸、挤压或错位。
整体分为三大固定区域：
左侧主内容区：宽度占终端总宽度 70%，高度占 85%
右侧状态侧边栏：宽度占终端总宽度 30%，高度与主内容区一致（85%）
底部输入区：宽度 100%，高度固定占 15%，始终固定在最下方
区域之间使用稳定的分隔线实现视觉隔离，分隔样式、位置、长度固定不变，不随内容动态变化。
2. 左侧主内容区（聊天与工作过程展示）
功能定位
用于展示完整任务生命周期、用户与多 Agent 的对话记录、各 Agent 执行过程与任务评审结果。
内容展示规则
清晰展示用户下发的任务、对话、指导指令
完整展示每个 Agent 的思考过程、执行步骤、中间结果、最终输出，不折叠、不省略、不合并
任务完成后自动展示 Review 结论：通过 / 需修改 / 驳回及详细意见
系统通知、状态切换信息以弱样式居中展示
视觉与交互
不同 Agent 使用固定前缀或标识区分，消息区块独立清晰
内容超出区域高度时，仅在本区域内部滚动，不影响整体布局
支持用户通过 @Agent名称 定向对话，指令会明确标记目标 Agent
3. 右侧状态侧边栏（实时监控面板）
侧边栏与主内容区等高、宽度固定，内部垂直划分为多个固定高度模块，整体不滚动、不变形。
模块构成
任务总状态模块
展示当前任务阶段：等待任务 / 任务执行中 / 评审中 / 任务已完成
当前工作 Agent 模块
高亮显示当前正在执行任务的 Agent 名称，附带工作状态标识
Agent 列表与状态模块
展示所有 Agent 及其实时状态：空闲 / 执行中 / 已完成
简要执行日志模块
展示最近几条 Agent 调度记录，内容固定条数，不溢出、不挤压其他模块
特性
侧边栏内容实时同步任务流程
不随主聊天区滚动，位置始终固定
模块大小稳定，信息层级清晰
4. 底部固定输入区
功能
用户输入对话、下发任务、定向指导 Agent 的唯一交互入口。
布局与交互
位置永久固定在终端最下方，不会被历史消息顶出视图
输入框区域高度固定，不随内容变化
支持输入 @Agent名称 实现对指定智能体的直接指挥
支持基本输入编辑与历史翻阅，不破坏上方布局
5. 核心业务流程
任务接收
用户在底部输入区下发自然语言任务，可 @指定 Agent，系统接收并调度执行。
工作过程可见
每个 Agent 按步骤输出执行过程，主内容区实时展示，完整可追溯。
任务 Review
任务执行完成后自动进入评审环节，评审 Agent 输出结论与建议。
迭代与修正
用户可根据 Review 结果，再次 @对应 Agent 进行修改、补充或重新执行。
6. 界面风格要求
纯终端字符界面，简洁、工程化、低视觉干扰
布局刚性稳定，区块边界明确，比例不变
信息层次清晰，便于快速识别 Agent 身份与任务状态
滚动行为仅发生在内容区内部，整体结构不抖动、不闪烁
