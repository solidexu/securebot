# 交互式委派创建使用指南

## 快速开始

### 方式1：快速模式（指定Agent和任务）
```bash
/collab delegate py 实现光流算法
```

系统会自动：
1. AI 分析任务，生成验收标准建议
2. 引导你确认验收标准
3. 询问期望交付物和上下文
4. 选择优先级
5. 显示摘要并确认

### 方式2：完整交互模式
```bash
/collab delegate
```

系统会逐步引导你输入：
1. 选择被委托者（从可用Agent列表）
2. 输入任务描述
3. 确认验收标准
4. 输入期望交付物
5. 补充上下文信息
6. 选择优先级
7. 确认创建

## 后续流程

### 1. 任务执行（自动）
被委托者会自动：
- 接受任务
- 执行任务
- 生成执行摘要和交付物清单
- 提交验收

### 2. 收到验收通知
```
⏳ 您有 1 个任务待验收！
   任务执行完成，需要您确认验收才能闭环
   • [10:30:00] → py: 实现光流算法...
   使用 /collab tasks 或 /collab review 验收
```

### 3. 验收任务
```bash
/collab review
```

查看：
- AI Review 总结
- 交付物清单
- 测试结果
- 自评报告

决定：
- 通过 → 流程闭环完成
- 驳回 → 提供反馈 → 重新执行

### 4. 查看所有任务
```bash
/collab tasks
```

查看委派出去和收到的所有任务。

## 特性说明

### 1. AI 自动生成验收标准
系统会分析任务描述，自动生成合理的验收标准建议，包括：
- 功能完整性
- 质量要求（测试覆盖率等）
- 文档要求
- 性能要求

### 2. 结构化信息
每个委派包含：
- 明确的验收标准
- 清晰的期望交付物
- 充分的上下文信息
- 明确的优先级

### 3. 迭代支持
- 最大迭代次数：5轮
- 每轮都有完整的执行和验收记录
- 驳回时提供详细的反馈

### 4. 完整闭环
```
委派 → 执行 → 验收 → 通过/驳回
                     ↓
               驳回 → 改进 → 重新验收
```

## 最佳实践

### 1. 明确的验收标准
好的验收标准应该：
- 具体、可验证
- 有明确的指标
- 覆盖关键功能和质量要求

示例：
```
✓ 单元测试覆盖率 > 80%
✓ API 响应时间 < 100ms
✓ 有错误处理和日志记录
```

### 2. 清晰的期望交付物
列出具体的文件和产物：
```
optical_flow.py - 核心算法
test_optical_flow.py - 单元测试
README.md - 使用文档
examples/demo.py - 示例代码
```

### 3. 充分的上下文
提供必要的环境信息：
```
工作空间: /workspace/py
Python 版本: 3.10
依赖: numpy, opencv-python
需要处理的视频分辨率: 1920x1080
```

### 4. 合理的优先级
- **high**: 紧急任务，关键功能
- **normal**: 常规任务
- **low**: 低优先级，可延后处理
